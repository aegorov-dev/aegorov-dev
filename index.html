🏢 О проекте

RPM (Research Publication Manager) — корпоративная платформа для управления полным жизненным циклом научных публикаций в одном из крупнейших академических издательств мира (Wiley). Система обслуживает 1700+ научных журналов и обрабатывает 500 000+ статей в год — от подачи рукописи до публикации.

Что решает RPM:

  • Управление производственным процессом статей (Article Tracking, Proof Production, Milestones)
  • Планирование выпусков журналов (Issue Builder, Pagination Sheets, Print-runs)
  • Оркестрация задач между внешними поставщиками и внутренними системами
  • Интеграция с upstream/downstream системами (Editorial Manager, WOL, CrossRef, PubMed)
  • Управление эмбарго, коллатералами, цветностью и пагинацией

Архитектурные решения с моим вкладом:

⚡
Event-Driven Architecture (Kafka)
Миграция с Tibco на Kafka для Production Listener. Асинхронная обработка событий от packagegraph-service. SASL-аутентификация, dead-letter queues, exactly-once semantics.
🔄
API Versioning Strategy
Спроектировал и провёл миграцию v1→v2 endpoints. Swagger-First подход: контракт определяется до реализации. Backward-compatible deprecation с grace period.
🔒
Optimistic Locking + Retryable
Реализация конкурентного доступа через version-поля + Spring Retry для автоматического повтора при OptimisticLockingFailureException. Применено в Article Embargo.
💾
Multi-layer Caching
Journal state caching, publishedOnline кэширование, embargo-state cache. Инвалидация через event-driven подход.
📦
Batch Processing Optimization
Batch-обновления с IS DISTINCT FROM для минимизации write-amplification. Сокращение lock-contention на production БД.
🎯
Job Orchestration Service (JOS)
Отдельный микросервис для оркестрации долгоживущих задач (Pagination Sheet generation, Print-runs). Разделение concerns между RPM API и вычислительными задачами.
🤖
AI Assistant (PoC)
RAG-архитектура: Azure OpenAI + векторное хранилище + MCP tools. Streaming через NDJSON, session-based chat memory, rate limiting per user. Интеграция через Spring AI.

Архитектурные принципы:

  • Swagger-First — API-контракт как source of truth, генерация кода по OpenAPI spec
  • Fail-Safe — retryable операции, graceful degradation, circuit breakers
  • Domain-Driven Design — bounded contexts (Journal, Article, Issue, Embargo)
  • Zero-Downtime Deployments — rolling updates в Kubernetes, backward-compatible migrations
  • Observability — structured logging, metrics, health checks, ArgoCD GitOps

🏢 About the Project

RPM (Research Publication Manager) — an enterprise platform for managing the full lifecycle of scientific publications at one of the world's largest academic publishers (Wiley). The system serves 1,700+ scientific journals and processes 500,000+ articles per year — from manuscript submission to publication.

What RPM solves:

  • Article production management (Article Tracking, Proof Production, Milestones)
  • Journal issue planning (Issue Builder, Pagination Sheets, Print-runs)
  • Task orchestration between external vendors and internal systems
  • Integration with upstream/downstream systems (Editorial Manager, WOL, CrossRef, PubMed)
  • Embargo management, collaterals, color use, and pagination

Architectural decisions with my contribution:

Event-Driven Architecture (Kafka)
Migration from Tibco to Kafka for Production Listener. Asynchronous event processing from packagegraph-service. SASL authentication, dead-letter queues, exactly-once semantics.
🔄
API Versioning Strategy
Designed and executed v1→v2 endpoint migration. Swagger-First approach: contract defined before implementation. Backward-compatible deprecation with grace period.
🔒
Optimistic Locking + Retryable
Concurrent access via version fields + Spring Retry for automatic retry on OptimisticLockingFailureException. Applied in Article Embargo feature.
💾
Multi-layer Caching
Journal state caching, publishedOnline caching, embargo-state cache. Event-driven invalidation approach.
📦
Batch Processing Optimization
Batch updates with IS DISTINCT FROM to minimize write-amplification. Reduced lock-contention on production DB.

Job Orchestration Service (JOS)
Separate microservice for long-running task orchestration (Pagination Sheet generation, Print-runs). Separation of concerns between RPM API and computational workloads.

AI Assistant (PoC)
RAG architecture: Azure OpenAI + vector store + MCP tools. Streaming via NDJSON, session-based chat memory, rate limiting per user. Integration via Spring AI.
